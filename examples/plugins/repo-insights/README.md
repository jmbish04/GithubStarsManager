# Repo Insights

A page-based sample plugin: clicking "Repo Insights" in the "Plugin Actions" menu of a repository card opens the plugin page inside a modal dialog, fetching GitHub API metrics for that repository in real time and rendering them into an analytics dashboard.

## Data Sections

| Section | Content | GitHub API Endpoint |
|---|---|---|
| Header + KPIs | Stars / Forks / Open Issues / Watchers / License / Created date (merged snapshot + real-time details) | `/repos/{owner}/{repo}` |
| Repo Health | Overall 0–100 score and A–E grade, computed locally on the page across three factors: maintenance activity (40%), popularity (30%), and quality (30%) | (Based on data above) |
| Repo Health Check | One-line summary (maintenance status + latest commit / latest release) + author and top contributors + objective facts grouped by relevance (updates / popularity / repo traits, with unknown items sorted to the bottom), matching the criteria of the "Repository Health Facts" panel in the Release sidebar; README presence is completed from community profile, and the latest commit is derived from weekly statistics | (Based on data above) |
| Commit Activity | Weekly commit bar chart for the last 52 weeks; commits over the last 4 weeks, change vs. prior 4 weeks, active weeks | `/repos/{owner}/{repo}/stats/commit_activity` |
| Code Churn | Weekly additions / deletions (bidirectional green / red bars) | `/repos/{owner}/{repo}/stats/code_frequency` |
| Language Distribution | Donut chart by byte share (Top 8 + Other) | `/repos/{owner}/{repo}/languages` |
| Maintainers & Contributors | Owner profile card (type, bio, blog, followers, public repos, joined date, `/users/{owner}`) + contributor summary list (commit counts and sample share) + bus factor analysis (minimum contributors needed to reach 50% cumulative commits in sample) | `/repos/{owner}/{repo}/contributors?per_page=12`, `/users/{owner}` |
| Release Cadence | Releases in the last year, average interval, latest release; monthly release bar chart and recent 5 releases list | `/repos/{owner}/{repo}/releases?per_page=100` |
| Community Health | Community profile completion score + 6 standard file signal badges | `/repos/{owner}/{repo}/community/profile` |
| Security Advisories | Published GHSA advisories count by severity and recent list | `/repos/{owner}/{repo}/security-advisories?per_page=10` |
| Star History | Weekly new stars bar chart + cumulative curve (up to 90 weeks; hidden automatically when endpoint is unavailable) | `/repos/{owner}/{repo}/stargazers/history?per_page=30` |
| Health Radar | Breakdown of key dimensions beyond the overall score (maintenance activity / popularity / quality / release cadence / community standards / security, with unknown dimensions omitted automatically) | (Based on data above) |
| Recent AI Highlights | Key highlight analysis generated by the user's configured AI combining recently merged PRs, Release changelogs, and commit statistics; requires `ai:invoke` permission, where the host displays the payload and asks for user confirmation each time | `/repos/{owner}/{repo}/pulls?state=closed` + Release logs |

## Permissions

| Permission | Purpose |
|---|---|
| `repositories:read` | Search and select loaded repositories when opened without repository context (from Settings); read snapshot metadata. |
| `network:api.github.com` | Initiate read-only GET requests to the endpoints listed above via the host's `network.request` bridge; authenticated by the host using the user's GitHub Token without exposing the Token to the page. |
| `ai:invoke` | Used only by the Recent AI Highlights card; displays the full prompt via the host and asks for user confirmation on every click. |
| `storage` | Cache results by dataset with freshness indicators (marked stale after 6–72 hours); opening the modal displays cached data first (even if stale) before refreshing in the background. |

## Installation

Go to Settings → Plugins → Install local plugin, select this directory (`examples/plugins/repo-insights`), and enable it after confirming permissions. Then click "Repo Insights" under "Plugin Actions" in any repository card's `…` menu.

## Implementation Details

- Pure static page (`ui/index.html` + `index.js` + `style.css`); charts use Chart.js UMD bundled with the plugin (same as the host BI dashboard), with no CDN and no inline scripts or styles (forbidden by page CSP).
- Opening the page issues approximately 10–13 read-only requests (concurrency limit 6); displays "Generating stats" when GitHub statistics endpoints return 202, while continuing to display cached data if available.
- `stats/*` endpoints may return 202 on first access (GitHub needs time to compute cache); handled accordingly by the plugin.
